# Demo audit, 15 November 2026

Reviewed the product API, job transitions, approval policy, worker recovery,
MCP and laboratory calls, browser states, test fixtures, and demo deployment.

- Repeated starts return the active run. A new investigation and approval both
  enforce the same queue caps. Approval and its audit record commit together.
- The worker commits the repair receipt, verification, action, and ticket
  outcome together. After a restart it can reconcile an existing receipt even
  if the operator requested cancellation after execution began. Verification
  matches the exact event as well as the expected state.
- A repeat investigation of an acknowledged webhook resolves without proposing
  a second delivery.
- Failed ticket loads have a retry control. A rejected rerun request keeps the
  last findings and draft. Ticket switches discard outdated requests. Waiting
  for approval no longer reloads the queue and account on every poll.
- Updated the transitive OpenTelemetry API to 1.45.2 to address [CVE-2026-126360](https://github.com/advisories/GHSA-mf5v-w3w3-f6cg).
- The root page supports HEAD and revalidates its HTML so clients can discover
  new assets after a deploy.

## Checks

45 backend tests, 15 browser tests, and 36 deterministic workflow cases. The
workflow evaluation had 36 expected dispositions, five verified repairs and
zero duplicate effects. Browser checks cover the ticket retry, preserving
findings and draft after a failed rerun, responsive layouts and automated
accessibility on the workspace, approval and settings views.

The public demo uses the included synthetic SaaS and the Offline driver. These
checks exercise the application and its approvals. They do not measure live
model quality. No payment or message is sent to a real service.
